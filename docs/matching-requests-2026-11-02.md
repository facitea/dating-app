# 추천 및 대화 요청 변경 (2026-11-02)

- 추천은 내 활성 조건을 그대로 충족하는 후보에서, 양방향 활성 조건·성향 적합도 순으로 우선 정렬한다. 나이/지역/MBTI/흡연/음주/종교 중 명시된 조건만 동일 가중치로 비교한다. 점수는 호감 확률이 아니다. 조건 미설정/모두 상관없음은 숫자를 표시하지 않는다. 상대의 구체적인 필터 값은 API에 노출하지 않는다.
- 과거 모든 DailyMatchCard의 배정 상대(열지 않은 카드 포함)를 사용자별로 제외한다. 현재 매칭/종료된 관계도 제외한다. 08:00/20:00 일정과 다음 회차 조건 반영을 유지한다. 후보가 부족하면 빈 카드 사유를 표시하고 자동 완화하지 않는다.
- 신규 유료 대화 요청은 10크레딧을 먼저 차감하고 첫 메시지만 보낸다. 받은 사람이 72시간 이내에 수락하면 계속 대화 가능하다. 거절/만료는 전액 반환하고 원장과 알림을 남긴다. 대기 중 상호 좋아요가 성사되면 무료 대화로 전환하며 반환한다. 수락된 유료 대화는 이후 만료/거절로 반환하지 않는다.
- 기존 대화방(DirectChatRequest 행 없음)은 기존처럼 이용한다. 과거 비용은 소급 반환하지 않는다. 거절/만료 후 같은 방으로 유료 재요청은 지원하지 않는다. 이후 서로 좋아요를 보내면 무료 대화로 전환 가능하다.
- 만료 작업은 app.notices.jobs=true(기본값)일 때 30초마다 최대 100건 처리한다. 중단 중 만료된 요청은 재시작 후 처리한다. 방 열람/수락 시에도 기한을 확인한다. 상태 전이는 ChatRoom 비관적 잠금, 잔액 변경은 CreditWallet 비관적 잠금으로 직렬화하고 반환 원장 키는 방별 유일하다.
- 테스트 DB는 신규 direct_chat_requests 테이블을 ddl-auto=update로 생성한다. 운영 배포에서는 명시적 마이그레이션과 백업이 필요하다.

## 성향 프로필 및 양방향 적합도

- `frontend/src/data/traitCatalog.json`의 89개 항목, 500개 키워드를 프런트엔드와 백엔드가 공유한다. Gradle processResources가 동일 파일을 클래스패스에 포함한다.
- 현재 선택 UI는 큰 카테고리별 최대 3개를 선택한다. 기존 저장 데이터와 서버의 세부 항목별 한도(성격 5개, 나머지 3개)는 호환성을 위해 유지한다. 내 성향과 상대에게 바라는 성향은 별도로 저장한다. 원하는 상대는 상관없음 또는 키워드를 직접 선택한다. 이전 SIMILAR 데이터는 읽기 호환을 유지한다. 미응답은 선택사항이며 추측으로 채우지 않는다.
- 가입을 14개 짧은 단계로 나누고 좌우 전환을 제공한다. 키워드는 대표 목록으로 축소하고 카테고리를 세로로 펼친다. 이전 선택은 목록에 남기며 색상과 개수로 선택 상태를 표시한다. 작은 화면이나 확대·키보드 환경에서는 내부 스크롤을 허용해 필드가 잘리지 않게 한다.
- 프로필 편집, 내 프로필, 상대 프로필, 관리자 재심사 화면에 연결한다. 승인된 성향은 ApprovedProfile 스냅샷에 보존하고 변경 내용은 재심사 승인 후 공개한다.
- 기존 나이·지역·MBTI·흡연·음주·종교 필터를 통과한 후보만 추천한다. 성향은 추가 필수 제외 조건이 아닌 추천 순서에 반영한다. 두 방향의 적합도 합계를 우선 정렬한다.
- 성향 항목 점수는 원하는 키워드 중 상대가 선택한 키워드의 비율이다. 비교 가능한 항목별로 동일 가중치를 부여하며 기존 조건 점수와 합산한다. 상관없음 및 정보가 없는 항목은 제외한다. 모두 미입력일 때 정보 부족을 표시한다. 실제 호감 확률 또는 행동 예측 모델이 아니다.
- 추천조건의 상대 성향 변경은 기존처럼 다음 08:00/20:00부터 적용한다. 첫 설정은 즉시 적용한다. 원하는 상대 성향은 추천조건에서 수정한다. 상대 프로필의 내 이상형 표시는 최신 저장된 pending 조건을 우선 비교하지만 실제 추천은 활성 조건을 사용한다. 기존 클라이언트가 성향 필드를 생략해도 이전 설정을 지우지 않는다.
- 수집 정보 및 추천 활용 안내와 동의 버전을 `2026-11-02-traits-test`로 갱신한다. 기존 프로필의 성향은 자동 생성하지 않는다.
- 검증: 백엔드 152개 테스트 통과(성향 검증·양방향 차이·다음 회차·재심사 포함), 프런트엔드 프로덕션 빌드 통과. 모바일 브라우저에서 가입 단계 이동, 키워드 선택 및 최대 개수 제한을 확인했다. 실제 이메일 인증을 포함한 신규 가입 전체 과정은 SMTP 인증 기능이 비활성인 현 환경에서 확인하지 못했다.
