# 보안·개인정보 점검 — 2026-10-29

## 범위
로컬 Spring/Vue 소스와 자동화·실행 테스트. 외부 침투 테스트, 전체 의존성 감사, 법률 자문을 대신하지 않음.

## 수정 사항
- 공유 X-Admin-Key 제거. 관리자 DB 계정/BCrypt, HttpOnly SameSite=Strict 세션, 8시간 만료, CSRF 헤더 검증. 계정당 5회 실패 시 15분 제한 + IP 로그인 제한.
- OWNER: 전체; REVIEWER: 조회 및 가입/프로필 심사; SUPPORT: 조회 및 문의/신고 처리; READ_ONLY: 조회만. 계정·감사기록은 OWNER만. 서버에서 강제. 관리자 사진 열람도 세션 필요.
- 계정 비활성화/권한·비밀번호 변경 시 기존 세션 폐기. 마지막 활성 OWNER 제거 방지. 변경·권한 거부와 로그인 결과 감사기록 저장(비밀번호·토큰·본문 제외).
- /uploads 정적 공개 제거. 사진 원본은 /api/media 또는 기존 /uploads 경로에서 매번 사용자 인증, 공개된 관계, 사진 장수, 승인 상태, 양방향 차단/신고, 매칭 해제, 탈퇴/정지 확인. no-store 적용. 승인 전 변경 사진은 상대에게 제공하지 않음.
- 타인 사진 URL 및 외부 URL 등록, 동일 URL 중복 등록 차단. 파일 경로 정규화와 실경로 검사. 업로드 실제 이미지 디코딩/재인코딩, 10MB/2천만화소 제한 및 메타데이터 제거. 웹 사진 편집기는 JPEG로 변환 후 업로드하며 직접 WebP 업로드는 서버 디코더에 따라 거절될 수 있음.
- 고정 JWT 키 제거: 로컬은 Git 제외 설정 파일의 무작위 키 사용. 기존 사용자 로그인 토큰은 재로그인 필요.
- 이메일 인증번호와 비밀번호 재설정 토큰을 응답으로 돌려주던 개발 경로 발견. 실발송 연동 전 기본 비활성화(503). 기존 이메일 비밀번호 로그인과 Google 로그인은 유지. 개발 전용 app.auth.dev-verification=true는 외부 서비스에서 사용 금지.
- 이메일 인증 오답 횟수가 트랜잭션 롤백으로 사라지는 문제 수정. 비밀번호 재설정 시 기존 세션 폐기.
- 사설망 전체 CORS 허용 제거, 정확한 허용 Origin 설정 사용.
- 약관 버전 2026-10-29-test; 운영자 양종현 / sku2013@naver.com. 실제 수집 항목과 현재 비활성화 방식·보관 현황 명시. /legal은 로그인 없이 접근 가능.

## 공개 출시 전 미해결 사항
1. 탈퇴는 비활성화이며 원본 사진·DB/백업 기록의 자동 파기가 없음. 목적별 보관 근거·기간, 정기 파기, 파일 정리, 외부 Firebase 계정 삭제/재가입 정책을 확정하고 구현해야 함. 실제 데이터 삭제를 이번 점검에서 일괄 실행하지 않음.
2. 종교 등 민감정보의 별도 동의와 Google/Firebase·브라우저 푸시의 처리위탁/국외 이전 적용사항 확인 필요. 현재 안내문은 정식 출시용 법률 검토 완료 문서가 아님.
3. 이메일/SMS 실발송 연동, 재설정 토큰을 수신자에게만 전달하는 절차 필요. SMS 개발 로그/테스트 설정은 운영 전 제거 필요.
4. HTTPS, Secure 쿠키, 정확한 운영 CORS Origin, DB·비밀 키·백업 접근 통제, 백업 복구 테스트 필요. 로컬 HTTP는 운영 보안 상태가 아님.
5. 크레딧 충전은 테스트 기능. PG·웹훅 검증·환불 없음. 실제 과금 금지.
6. 업로드 교체/실패 후 미참조 파일 정리와 보관 만료 작업, 업로드 횟수 제한 필요. 기존 공개 사진을 상대가 이미 저장한 사본은 회수 불가.
7. 기존 Firebase 의존성 트리와 프론트엔드 의존성 감사 경고는 별도 확인 필요. 이 작업으로 모든 취약점이 제거되었다고 보장하지 않음.

## 운영 방법
관리자 로그인: /admin/overview. 최초 계정은 backend/.local/admin-first-login.txt에서 확인 후 관리자 계정·권한 메뉴에서 비밀번호 변경. 초기 계정 생성은 DB에 관리자가 없을 때만 수행하며 이후 설정 파일을 바꾸어도 기존 비밀번호를 덮어쓰지 않음. backend/.local/admin.properties와 Firebase 파일, frontend/.env.local은 Git 제외; PC 이동 시 별도 보관/복사.
서버는 backend 디렉터리에서 실행. 공개 운영 시 app.auth.refresh-cookie-secure=true, app.cors.origins에 HTTPS 프론트엔드 주소 지정. 비밀 키를 Git에 추가하지 말 것.

## 추가 인증 점검
- 화면에서 제거됐지만 남아 있던 전화번호 자동가입/로그인 API를 410으로 종료. 가입 약관·성인 확인을 우회하는 별도 가입 경로를 차단. 가입 후 프로필 전화번호 인증만 유지.
- 회원 로그인 실패 횟수는 별도 트랜잭션에 저장하여 실패 응답 롤백으로 제한이 사라지지 않도록 수정. 프로필 전화번호 인증 오답 횟수도 유지.
- 갱신 토큰 조회에 DB 쓰기 잠금을 적용하여 동시 재사용 시 중복 갱신을 방지.

- 운영 전 알려진 비밀번호의 더미 계정과 테스트 충전/시드 설정도 별도 정리 필요.
